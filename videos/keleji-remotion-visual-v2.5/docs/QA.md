# V2.2 畫面品質檢查

2026-10-28 UTC。交付為風格化編輯式物件動畫，不是擬真液體或實拍倒奶。

## 已完成的迭代

1. 素材檢查：同atlas的盒與玻璃杯，深藍／米白／黃，保留材質與高光；紙盒／玻璃風格一致且清晰。
2. 第一批0/26/44/65/90/119格檢視：發現倒入盒太接近左邊界、液帶與背景對比不足、鏡頭移動後桌面範圍不足。
3. 修正核心層：移動倒入姿態，保持盒嘴與流體落點座標連動；強化液帶寬度／輪廓與液面；桌面延伸到畫外。未增加文字特效掩蓋問題。
4. 540×960、30fps、4秒低解析MP4與0.5秒間隔對照圖檢查後，渲染正式版本。
5. 開啟Remotion Studio實際組件預覽，確認Composition載入；另輸出與渲染同源的完整關鍵影格。

## 動作與圖層

- 盒提起與傾斜 → 流體前緣從盒嘴發展 → 接觸杯底／液面後液面上升 → 停止後尾段繼續落下 → 杯內波紋收斂 → 鏡頭停在杯子。
- 液帶是封閉、厚度變化、飛行前緣與停止尾段的形狀；杯腔、前後杯壁、液面分層遮罩，非一條白線假裝擬真模擬。
- 盒的軌跡有目的和終點，沒有自動循環漂浮、彈跳、隨機粒子或CSS即時動畫。
- 65格可見倒入與杯內上升；90格可見停止後尾段；119格杯子穩定。最後鏡頭讓盒子部分離開左邊界，是聚焦杯子的有意構圖，不是素材邊緣破圖。
- 主要標題穩定在同一空間；不是整頁文字／Icon輪播。畫面內標示「風格化動畫示意」。
- 程式僅近似液體流量與到達延遲，不提供流體力學、毫升或營養數據精度。

## 正式輸出驗證

FFprobe：H.264、1080×1920、30/1fps、120格、4.000秒、無音軌。實際像素格式yuvj420p（全範圍4:2:0），設定與數字詳見qa-metrics.json。
全部120格解碼成功，沒有黑幀。低解析逐格灰階平均差最大6.347/255，發生第90格（回桌與鏡頭運動重疊處）；預覽與主要格檢查未見不合理跳切。這不是能自動證明所有觀眾不感卡頓的指標。
直接Remotion PNG與正式MP4對應六格比對：平均RGB誤差約1.43–1.55/255，符合本次有損H.264壓縮預期，沒有不同狀態或錯格。
非順序測試順序65→119→65：畫面狀態一致，桌面細邊界有最多1/255抗鋸齒取整差，平均差0.0000111/255；最終版本不是逐位元組相同PNG。最早迭代曾byte-identical，但以最終量測為準。
verify-seek.mjs保存兩次影格；qa_video.py以最大1、平均小於0.001的RGB差作檢核，不掩飾此微小像素差異。
影格函式未累加任何時間狀態；FontFace與Img載入等待明確，避免首格字型或圖片閃爍。

## 重跑驗證

```bash
npm run typecheck
npm run render -- --preview
npm run render
npm run frames
node tools/verify-seek.mjs
ffmpeg -y -v error -i out/milk-pour-4s-1080x1920.mp4 -vf "select='eq(n,0)+eq(n,26)+eq(n,44)+eq(n,65)+eq(n,90)+eq(n,119)'" -vsync 0 out/decoded/frame-%02d.png
python tools/qa_video.py
```

先建立out/decoded。人工／視覺檢視範圍是六個主要影格與低解析0.5秒間隔圖，配合全片解碼、逐幀統計及跳轉測試。正式影片動態節奏與美術是否達標，仍請使用者實際觀看；未自動擴作12秒或接入自動製片流程。
