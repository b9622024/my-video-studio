# 可樂吉 V1.2.3｜單一載荷的飯匙交接研究

本輪是3秒、540×960、30fps的**私人物件互動測試**。同一把空飯匙本體加上一個可分離的新米飯載荷，接觸既有飯堆後，飯匙從載荷下方抽離，米飯留在盤上。這是概念動畫，不是真實拍攝、實際量測或正式公開核准。

## 1. 現有素材準備度

| 檢查 | 原始六個資產的問題 | 本輪處理 |
|---|---|---|
| 相同飯匙形狀 | 空匙／載飯匙並非精確註冊，畫布及輪廓不同 | 全程只使用原`paddle-empty.png`本體，不交換兩把匙 |
| 可分離匙上白飯 | `paddle-loaded.png`將木匙與白飯烘焙一起 | 用內建圖像編輯工具補一個獨立RGBA載荷；原載飯匙不進動畫 |
| A→B是否可新增 | A/B/C為獨立生成的完整飯堆，米粒不連續 | 原A始終保留；結果是**原A＋一個新增載荷**，不冒稱等於原B |
| 遮擋與接觸 | 缺少動作深度與接觸關係 | 固定盤底、飯匙、原飯堆前景、新載荷分層；接觸處有前景遮擋與alpha投影 |
| 卸飯中間態 | 沒有可直接切換的AI動作序列 | 以單一物件來源及連續Remotion位置約束計算中間態，不生成四張互不相同的整景替代它 |

原始六個PNG逐一核對V1.2.1雜湊，沒有覆寫。M1、M2、V1.2.1、V1.2.2 A/B及其程式、素材、歷史影片保持原樣；A保留備用比較，B未繼續優化。

## 2. 新增資產與失敗紀錄

- `assets/generated/payload-original.png`：第一個AI隔離載荷。置於實際場景後米粒過細，與原飯堆接觸處材質不一致，**中間影格否決，未為該材質版本輸出影片**。
- `assets/generated/payload-fewer-grains.png`：第二個AI修正載荷，減少可見粒數、增加單粒相對大小，以原A的短米粒、米白色、光源為參考。
- `assets/derived/payload.png`：第二版載荷的低alpha邊緣整理版。固定物件寬度67邏輯像素，整段沒有縮放動畫。這是米粒尺度註冊，不能把原始像素尺寸當作食物量。
- `assets/derived/paddle-empty.png`、`assets/derived/rice-A.png`：原空匙／基礎飯堆的可撤回低alpha整理版。沒有重畫食物或木匙主體。舊資產的高alpha主體RGBA保持相同；新生成載荷重輸出時最多1個8-bit色階的量化差，alpha不變，詳見`assets.json`。
- `frame-*.png`：由**同一套分層資產及同一套連續曲線**產生的註冊中間影格，不是AI重新生成完整場景。
- `attempt-1/`：保留第一版失敗樣本及當時配置；審核包收錄代表影格，工作目錄保留完整樣本。

來源是內建`image_gen.imagegen`，沒有接入新付費API。兩次生成的來源鏈與原始保存路徑在`payload-provenance.json`，提示詞在`GENERATION.md`。模型版本、seed沒有由工具提供，不虛構；重跑提示詞不保證像素相同，精確重建須用交付的PNG。沒有生成新餐盤／蔬菜／雞肉，沒有使用C1照片、lighten blending或重複米飯貼圖。

## 3. 動作與實際機制

本測試採**黏合小飯團的滑卸**：原飯堆提供止擋，木匙回抽，單一載荷相對匙面移動，最後固定在盤面。沒有宣稱逐粒米飯散落、軟體變形或真實力學模擬。飯匙視角與平面方向全程固定，避免工具形狀／光照因換圖而跳動。

| 幀／時間 | 事件 | 可見結果 |
|---|---|---|
| f0–6／0–0.2秒 | 起始 | 原飯堆與餐盤固定，匙與載荷尚在畫面外 |
| f6–27／0.2–0.9秒 | 載飯進場 | 載荷以固定相對座標隨同一把匙進場 |
| f27–36／0.9–1.2秒 | 接觸 | 匙前端接觸原飯堆，原飯堆前景遮住部分匙面；載荷接近並碰到原飯堆 |
| f36–60／1.2–2秒 | 滑卸交接 | 飯匙向柄的方向抽回，載荷連續向盤面停留位置移動，與匙的重疊逐漸減少 |
| f60–82／2–2.733秒 | 空匙離開 | 載荷已固定在盤面，空匙撤離；沒有把載飯匙淡化成空匙 |
| f82–90／2.733–3秒 | 結果 | 原飯堆＋新增載荷保留，匙完全離場 |

時間窗為[start,end)，相機固定。工具、載荷、原飯堆與盤子的每幀位置／相位在`pose-samples.json`，事件表在`timeline.json`。米飯來源不切換、沒有米飯透明度動畫、沒有米飯尺寸動畫，沒有粒子、滑桿、空碗交換、字幕或配音。畫面只有小型「概念動畫」識別。

圖層順序：固定餐盤／蔬菜／雞肉 → 同一飯匙 → 原A飯堆前景 → 唯一的新米飯載荷。陰影來自各物件alpha及少量位置／高度代理值，不使用幾何圖案畫食物，也不以陰影掩蓋形狀不一致。

## 4. 中間影格檢查及其限制

已檢視實際f18、27、36、48、60、89影格後才開放影片渲染。第一版材質失敗有保留；第二版經固定尺度註冊後，飯匙本體沒有變形、載荷能跟隨、接觸、離開匙面並留在盤上。這是**助理的私人測試預檢，不是使用者人工美術核准**。

原生alpha投影診斷作為接觸輔助：載荷在進場／接觸初期位於匙輪廓內；f36與原飯堆有接觸重疊；f48與匙的重疊約40%；f60與匙已分離，並與原飯堆相連；f60之後載荷位置完全不變。這些是屏幕像素與2D遮擋，不是物理支撐力、3D無穿透證明或食物份量數據。

幀邊界前後的載荷位置連續，沒有因切換附著約束而瞬移；全段來源資產與固定尺寸保持一致。輸入JSON有向量、時序與尺寸驗證，原圖及衍生檔亦有雜湊檢查。渲染入口會拒絕缺少／過期的中間影格檢查，不提供強制略過選項。

最後檢查包含：TypeScript嚴格模式、附著／交接／結果位置測試、接觸影格、實際編碼MP4影格、90幀／3秒／30fps／無音軌／全段解碼，以及舊素材與舊影片雜湊。渲染成功本身不構成美術通過。

**仍需你實際觀看確認**：

- 小飯團滑卸是否自然，而非像剛性貼片；這個版本沒有模擬米粒鬆散、塌落或重新分布。
- 新舊米粒的尺度、光澤、色溫及接觸接縫是否足夠一致。
- 接觸／退匙節奏、前景遮擋與2.5D投影是否合理；這不是已校準的3D碰撞及光照模型。
- 若需要傾匙、逐粒卸飯或明顯變形的流動，現有正面固定PNG不足，需要同一工具的註冊傾角素材、米粒釋放中間態或3D資產，不能拿完整飯團淡化交換補救。

本輪只將它列為**可供驗收的單一黏合載荷交接測試**，未宣稱完成自然的逐粒添飯，也未核准正式公開或與M1/M2串接。

## 5. 可重用範圍與JSON

`PayloadTransferStudy`＋`TransferMath`是一個小型、資料驅動的交接模組：

- 可替換底圖、固定承接物、工具本體、唯一可分離載荷。
- 原生像素錨點、固定尺寸、接觸位置、進場／退出Bezier控制點由JSON提供。
- 可調整進場、接觸、滑卸、完全分離、離場幀；附著與落定位置連續。
- 畫布尺寸／幀率／總幀數由Composition讀取設定；畫面邏輯為9:16，原型輸出只使用540×960。
- 可用事件幀對齊後續旁白，但本輪不處理音軌或修改GPT-SoVITS。

它適合一個完整黏合／剛性載荷由工具交付到固定承接物，不自動支援液體、軟體、鬆散米粒流動、工具3D傾轉或任意碰撞。替換素材仍要重新註冊與檢查，不把「可重用」說成任何圖片都能直接自然互動。

## 6. 重建與驗收關卡

程式、設定、JSON、提示詞與雜湊保存於GitHub；PNG、MP4與失敗樣本只在私人審核包。若用現有包重播，可將其`assets/`放到`.runtime/v123-public/assets/`，將已審核`frame-*.png`放到預設輸出目錄，再執行渲染。不要把中間影格pass當成公開素材授權。

```bash
cd broll-pipeline
# 若重做資產準備，可從本輪包或原V1.2.1包讀取原始檔；不下載素材、不讀API Key。
python tools/prepare-v123-assets.py --source /private/broll-v123-interaction
node tools/build-v123-timeline.mjs
node tests/transfer-v123.test.mjs
python tools/inspect-v123-contact.py
REMOTION_HOST=/private/existing-v2.5-host node tools/render-v123-interaction.mjs --stills
# 檢查實際中間影格；輸入或來源改動時舊review會失效，不能自動沿用pass。
REMOTION_HOST=/private/existing-v2.5-host node tools/render-v123-interaction.mjs --render
python tools/package-v123-interaction.py
```

`intermediate-review.json`綁定配置、資產清單、元件來源與已檢查影格的SHA-256。修改後必須重新檢查並記錄該版預檢，否則`--render`停止。沒有`--force`；預設只產生靜態中間影格。精確重播以已交付資產為準，重新準備資產或更換平台產生不同像素時要重新檢查。

沿用原Remotion4.0.539／React／Chromium與Python Pillow、Playwright、FFmpeg，不重建引擎、不新增付費服務或GPU。iPhone直接開MP4／PNG或解壓審核包即可，不必自行架設伺服器。
