# 技術可行性與美術／科學風險

## 已完成與待完成

已完成：原片影格觀察、兩個硬切相鄰影格確認、四張原創540×960向量關鍵構圖、分層靜態合成、鏡頭／事件JSON。這不是8秒動態成品。未進行觀眾、實體手機或工程師驗收。

沿用：Remotion renderStill、AbsoluteFill分層、SVG路徑與遮罩、V201的八段塔身設計語言、影格驅動元件習慣。新分支沒有改動任何舊Composition。HyperFrames與GSAP不需介入本輪。

新增但範圍受控：
- Tower：可撓曲的原創101版本，底部固定、上部逐漸增加偏移；不旋轉整張圖。
- Skyline／Street：遠景城市與前景平台，避免主物件孤立在空白底。
- Chamber：剖面後壁、梁、吊索、球、托架與兩支投影連桿。
- DamperLink：固定端與移動端以同一組端點生成缸體、活塞及關節。
- Layer：各SVG層共用世界／攝影機換算；城市視差與建築結構不同。局部結構與互動元件使用相同camera以免端點脫離。
- 外牆局部遮罩：只揭上層，不拿走整座建築。

現有工具可完成推近／退鏡、局部外牆遮罩與結構遮擋、線條風向、同尺度比較。**下一階段才新增**影格狀態、耦合運動求解、時間壓縮與連桿行程驗證；本輪未寫好一支8秒片再要求追認。

## 科學邊界

依[台北101官方裝置說明](https://www.taipei-101.com.tw/en/observatory/feature)，TMD為被動減振系統，金色質量由纜索懸吊，下方液壓阻尼器協助耗能。另以[製造商A+H案例](https://ahcustom.com/tuned-mass-dampers/case-studies/taipei-101/)核對質量塊與連接構件角色。本輪不使用這些頁面的量測數值或減振百分比，也不把頁面數值回填成動畫工程參數。

下一階段建議以無因次的兩自由度示意模型，同時求解建築x與質量y：

```
mb*x'' + cb*x' + kb*x + cd*(x'-y') + kd*(x-y) = F(t)
md*y'' + cd*(y'-x') + kd*(y-x) = 0
```

這只是選型方向，**尚未設定或求解**，不代表台北101精確設計。不可用y=-x固定反相。阻尼力與相對速度相關；應檢查耗能方向與穩定性。兩個比較實例共用相同外力與建築設定，只有裝置不同；不能一邊減弱風力來假裝裝置有效。8秒是教學敘事時間，不宣稱真實振動週期。

本輪靜態球體採相同局部懸吊長度下的弧線高度，投影吊索連到同一托架；之後需逐幀檢查端點、缸體行程、穿透和動作相位。構件數量、樓板位置、球體比例都是簡化示意，不是施工剖面圖。

|球與懸吊辨識|4|球、雙投影吊索束、梁、托架與缸體同場；不能誤認成自由球|
|景別進展|4|城市全景→上層中景→機制特寫→外觀比較；動態轉場未實作|
|美術一致性|4|統一米白／墨色／綠，金色只給裝置；特寫會放大描邊，需動畫實看|
|手機可讀性|3|特寫球體直徑約150px，中景約90px；末段小裝置不能作主要資訊，需手機確認|

事件理解與動作自然度：**未評分、未驗收**，靜態圖不能證明。僅可說分鏡有安排外力→回應→探索→互動→結果。

風險與下一輪否決條件：
1. 外牆退場像揭資訊卡、失去實體建築定位：保持牆邊／樓板與同一相機，不以整棟消失替代。
2. 球與建築永遠同幅反向、纜索鬆脫、托架未接球或活塞穿透：不得進入交付，先修模型／幾何。
3. S04雙塔看成兩棟真實建築：明確標示概念比較；純視覺版也保留必要的非實測註記，或經核准改成單棟前後同尺度。
4. 結果因風停止而非裝置效果：比較必須共用外力，不從不同輸入挑畫面。
5. 八秒內鏡頭過忙：S03主體靜鏡閱讀、S04至少約1.1秒回收；必要時減少展示細節。
6. 技術輸出成功被當成美術通過：測試、製作者自評、人工核准旗標分開保存。
