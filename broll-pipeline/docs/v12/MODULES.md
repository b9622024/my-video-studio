# 可樂吉 V1.2｜三個獨立模組測試

本輪根據使用者明確指定 A1、B1、C1 的新指示，製作獨立模組測試。此測試授權不修改原本 A1／B2／C2 的正式選片紀錄、不視為 V1.1.2 靜態構圖已核准，也不產出新的 12 秒成片或正式發布版。

## 分鏡與動畫事件

| 模組 | 0–0.6／0.8 秒 | 核心事件 | 收束 | 素材 |
|---|---|---|---|---|
| M1 Plate Overview，2.5秒 | 原片切肉近景，取景1.22倍 | 0.6–1.5秒回到原始取景，讓肉與蔬菜同時可見 | 1.5–2.5秒取景穩定，影片繼續；主標「先看整盤。」 | A1 1.00–3.50秒，原速 |
| M2 Vegetable Focus，2.5秒 | 鍋內聚菜、鍋鏟靠近 | 0.8–1.8秒實際撈起離液 | 1.8–2.5秒托住蔬菜，仍為影片；主標「蔬菜，也要看見。」 | B1 35.10–37.60秒，原速 |
| M3 Rice Portion by Need，3秒 | C1 白飯實拍0–0.8秒 | 0.8秒切入同一固定餐盤概念；1.6秒、2秒先後增加米飯影像，呈現少／中／多 | 2.4–3秒保留同盤狀態，主標「主食份量，依需求調整。」 | C1 8.00–8.80秒；概念照片取自9.50秒 |

逐影格事件定義見 `projects/modules-v12/events.json`，所有事件均由 Remotion 影格計算，沒有 GSAP、隨機、計時器或持續漂移圖層。主標出現只作結論，不承擔主事件。小標為「可樂吉 ／ 餐點筆記」。M1、M2 補充字分別為「先看一餐，再看細節。」「不是點綴，是配菜的一部分。」；M3 為「先看實際餐點，再回到自己的需求。」

### M3 的真實影像與概念邊界

- 開場是實際 C1 影片；後段是**明確標示的概念合成**，不是原片真的添飯／減飯。盤為單一固定、平面黑色餐盤參照，沒有空碗交換或假立體旋轉。
- 使用 C1 真實米飯照片作遮罩，以相同米粒尺度的影像層逐步增加占用面積，不以放大整張照片冒充整盤攝影機移動，也沒有程式繪製食物。
- 少／中／多僅表示這個合成內的相對狀態；沒有克數、熱量、比例、等量飯匙假設或唯一正確份量。最末仍在「多」並非推薦多吃；沒有勾選或評分暗示任何狀態較好。
- 沒有新的蔬菜／蛋白質素材，因此不憑空補造其他食物。只改變同一餐盤中的米飯影像，參照盤位置保持不變。
- 遮罩與重疊影像仍屬概念視覺，不是寫實盛飯紀錄；重複紋理、遮罩邊界及構圖品質須由使用者看影片驗收。不能以技術渲染成功代表美術已通過。

## 關閉文字時的檢查

M1 可見由較近回到較廣的餐點視角；M2 可見鍋內到托起的事件；M3 可見固定餐盤上米飯影像逐次增加。附去主標版本供直接檢查；M3 仍保留「概念合成／非量測」的小型識別，避免摘錄被誤認實拍紀錄。

**M1 素材限制**：A1 原片本身只有肉與沙拉近景，沒有完整盤緣或俯拍全餐。本版最多拉回原始視野，不能補出原片外的餐盤。若驗收要求「看見完整一整盤」，M1 應標記需補素材：建議原生直式、完整盤緣可見、由細節移至整盤或固定全盤鏡頭。尚未聲稱本素材已完整達成此條件。

**M2 素材限制**：使用原片較寬取景而非前版608像素窄裁；影像窗540×650，相當於原片約897×1080取景，保留約46.7%原寬，主體較完整。但 B1 撈動本身仍有自然動態模糊，沒有強力銳化或 AI 修復。

## 共用元件與重複使用

- `MealModule`：依 JSON 選擇近→廣的餐點觀察、真實蔬菜動作、實拍→概念份量的三種事件結構。
- `MealCaption`：共用極簡標題層，文字可關閉；位置避開食物主事件。
- `RiceStateStudy`、`RicePhoto`：固定盤參照＋來源照片遮罩＋資料化層次狀態，不能將其當作量測或實拍證據。
- `modules.json` 可改素材路徑、起點、標題、補充字、時長及米飯狀態層。換題材不必重寫整個 React 元件，但原片動作區間與遮罩仍須人工確認，不宣稱能無審核自動適用任意影片。
- 以540×960邏輯畫布設計，`useVideoConfig` 按輸出寬度縮放；既有 host 可註冊1080×1920、30fps。**本輪只輸出540×960預覽**，1080的文字與幾何尺寸可倍增，原素材的有效細節不因此增加。

## 重建與驗證

使用原有V2.5的Remotion4.0.539／React／Chromium執行環境，不重建或修改影片引擎。此環境的 OffthreadVideo 本機解碼橋接曾發生 Request closed／Failed to fetch，磁碟檢查仍有足夠空間，不能照錯誤提示誤判素材失效。本版因此以 FFmpeg 將原片連續解碼為 PNG 影格序列，交由同一個 Remotion Composition 逐幀播放；不是單張照片定格或假動作。A1原生25fps轉30fps只重複影格，B1/C1原生30fps；影格數、來源起點與集合雜湊記錄在 sources.json。元件仍保留其他環境可用的 OffthreadVideo 接口，不修改舊版引擎。

```bash
cd broll-pipeline
python tools/prepare-v12-modules.py --a1 /private/A1.mp4 --b1 /private/B1-large.mp4 --c1 /private/C1.mp4
REMOTION_HOST=/private/existing-remotion-host node tools/render-v12-modules.mjs --stills
REMOTION_HOST=/private/existing-remotion-host node tools/render-v12-modules.mjs
REMOTION_HOST=/private/existing-remotion-host node tools/render-v12-modules.mjs --clean
python tools/package-v12-modules.py
```

需要FFmpeg、Python Pillow（聯絡表用）、Noto Sans CJK字型及既有Remotion host依賴。準備腳本先比對原片雜湊，不下載或讀取API Key；使用其他來源須先建立新的合法來源與審核紀錄。Remotion bundler需正常本機HTTP監聽權限。render入口只允許獨立預覽／關閉標題預覽／靜態影格，不建立正式選片清單或完整成片。預覽可直接在對話或iPhone「檔案」開啟，不需要自行架設伺服器。

預覽採 H.264、BT.709、YUV 4:2:0。測試包含全段解碼、尺寸／幀率／幀數、影格非順序重繪一致性、原核准檔與舊影片雜湊、TypeScript與React結構檢查。影片美術品質與敘事是否通過仍待使用者驗收。
