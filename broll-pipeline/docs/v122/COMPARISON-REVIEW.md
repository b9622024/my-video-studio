# 可樂吉 V1.2.2｜三狀態餐盤私人比較研究

本輪授權僅限使用既有四個原創PNG進行私人動態研究，不代表公開素材核准。沒有飯匙添飯、沒有新生成餐盤／食物、沒有正式12秒影片。M1、M2、Pixabay API、HyperFrames、GPT-SoVITS與V1.2.1原圖／程式均保留。

## 兩支4秒預覽

兩案均為540×960、30fps、120幀、H.264／BT.709，無配音／音軌。米飯只有「較少／中間／較多」標籤，另保留「概念示意」小字。B的底部識別使用淡紙色安全區，保持旁盤經過畫面下緣時的文字對比。沒有數量、克數、熱量、推薦比例、正確答案或標準份量。

### 方案A：同位置Match Cut

| 畫格／秒 | 畫面及文字 | 相機／物件 |
|---|---|---|
| f0–39／0–1.333秒 | 較少，State A | 固定餐盤中心(270,450)，大小540；同一原圖底層 |
| f40–79／1.333–2.667秒 | 中間，State B | 相機及餐盤不變，白飯只替換為獨立B資產 |
| f80–119／2.667–4秒 | 較多，State C | 相機及餐盤不變，結束於C |

三態各40幀，相同時間、字級及顏色。f40、f80直接Match Cut；**零交叉淡化、同一時間只有一個米飯狀態**。這是狀態對照，不是實際添飯或米粒連續生長。所有狀態使用既有一致的前側接觸錨點；輪廓本身隨狀態改變屬比較內容，不用形變／淡化冒充連續事件。

### 方案B：同一虛擬桌面的攝影機

桌面三盤從頭就存在，物件不進場、不漂浮、不移動。固定世界座標：A(0,0)、B(580,100)、C(290,630)；每盤大小都是540，方向0°。使用原有近俯視美術，單一正交2.5D相機做平移及一致縮放，沒有宣稱建立真實3D網格或改變食物透視。

| 畫格／秒 | 相機世界座標／倍率 | 目的 |
|---|---|---|
| f0–18／0–0.60秒 | (0,0)、0.84 | 觀察A |
| f18–39／0.60–1.30秒 | 平滑移至(580,100)、0.84 | 沿桌面觀察B |
| f39–54／1.30–1.80秒 | 保持B | 讀取中間狀態 |
| f54–75／1.80–2.50秒 | 移至(290,630)、0.84 | 斜向觀察C，避免水平卡片輪播 |
| f75–88／2.50–2.933秒 | 保持C | 讀取較多狀態 |
| f88–103／2.933–3.433秒 | 拉回(290,315)、0.43 | 建立三盤同桌的比較關係 |
| f103–119／3.433–4秒 | 保持總覽 | 三盤等大，無任何正解突出 |

聚焦時每盤約454px，總覽約232px；總覽用於看相對狀態，不能用來審查米粒邊緣。攝影機只在兩次移鏡及最後一次拉回時移動，停留段位置完全不變；五次平滑多項式確保起訖速度／加速度歸零，沒有彈跳或持續漂移。

標籤固定在各盤的世界位置，**餐盤及文字完整入鏡才顯示**，避免旁盤只露一角時閃出被裁切文字。實際標籤出現的逐幀區間在`timeline.json`，標籤／狀態區間採[start,end)，相機keyframe則為精確幀點；`camera-samples.csv`記錄全部120幀的相機與可見標籤。這不是飯量物理增加的鏡頭。

## 美術修正與V1.2.1差異

1. 原圖另存於`assets/original/`，逐檔SHA-256比對V1.2.1。没有重生成或覆寫。
2. 米飯的衍生PNG在`assets/clean/`：只整理低alpha邊緣；alpha≤0.1壓到0，0.2映射至0.18，alpha≥0.3維持原值。不使用色鍵照片遮罩、描邊、重新畫米粒、重複飯團或lighten blending。
3. 實際像素比對：原圖alpha≥240/255的主體RGBA完全相同。保留alpha總量約99.0%–99.3%；這是像素透明度統計，不是實際食物量／形狀品質分數。低alpha輸出可能有PNG量化差異，不把它說成所有像素都未變。
4. 原生米飯陰影仍保留，另用米飯自身alpha的小幅接觸投影補強盤面關係；盤子以緊接觸＋柔和環境投影建立桌面厚度。這些是透明物件的2.5D渲染陰影，不是新畫的食物或物理光照模擬。參數均在`config.json`，可撤回。
5. 以540畫布比較：A的餐盤尺寸由V1.2.1等比約500增至540，頂端由225移至180。拿掉上方品牌與長標題，只保留狀態及小型概念識別；減少上方留白。
6. B使用完整共享桌面、三角空間位置及唯一相機變換，沒有簡報卡框、獨立物件左右進場、裝飾圖形、滑桿、粒子、飯匙或空碗交換。

`A-before-art.png`與`A-60.png`在**同一新版構圖**比較原始資產效果與新alpha／陰影效果，不是把它冒稱原V1.2.1完整排版。`art-difference.png`提供並排對照。

## 品質檢查：技術證據與美術判斷分開

- 原圖、V1.2.1所有審核資產／狀態圖、V1.2歷史影片雜湊比對。
- 米飯高不透明度主體RGBA保留；不以修改低透明邊緣來偷偷換米飯形態。
- A在各停留段的去標籤PNG完全一致；跨狀態固定餐盤、蔬菜、雞肉區域一致，差異限於白飯區域。切換前後幀另列出，沒有兩態重影過渡。
- B在各相機停留段PNG完全一致；每個物件的座標、尺度、資產固定。相機座標／倍率每幀驗證有限且在指定範圍，末幀三盤／標籤完整可見。
- 兩案非順序請求同一幀的PNG一致，TypeScript與時間／相機測試通過。音軌、長度、幀率、幀數與全段解碼另檢查。
- 從實際MP4擷取切換附近與移鏡中影格，對照原始渲染，避免只看靜態圖或只看「渲染成功」。

**初步目視判斷**：A的主體與飯量差異較容易閱讀，適合作為本輪優先比較候選；B能建立同桌空間關係，但4秒內兩次移鏡加一次拉回節奏仍緊，結尾單盤也較小，**不建議直接當成公開定版**。兩案都沒有被標記為人工美術通過。

仍需人工實際播放確認：B移鏡舒適度、縮小／移動時細米粒的取樣閃爍，米飯原生陰影與補強陰影是否出現過重邊圈，以及三態的生成透視／粒徑是否自然。停留幀完全一致只排除來源動畫閃爍，不代表H.264壓縮、手機縮放或藝術品質已完全驗收。

若A的Match Cut仍被看成物件跳位，或B仍像輪播／移動過快，應回報方案未達標，再調整構圖、觀察時間或刪除不必要相機段落；不以增加特效、長交叉淡化或虛構添飯補救。本輪維持兩個4秒研究輸出，不自行加長或串成正式影片。

## 可重用元件

- `LayeredObject`：原生alpha底層＋一個狀態層，資產與局部矩形均由資料指定。
- `MatchCutComparison`：任意狀態清單、固定相機及狀態停留幀數；不做食物形變。
- `TableCameraComparison`：固定場景物件、唯一2.5D相機、可配置世界位置及相機keyframes。
- `ComparisonMath`：逐幀狀態選擇、平滑相機及標籤可見規則，無計時器／隨機值／GSAP。

元件可替換成其他原生alpha物件／狀態資產，無須重寫整個React影片；但新資產的形態、陰影與布局仍需審核。本輪的alpha曲線只對既有白飯做了檢查，不宣稱能無條件套用到任何圖。

本輪新私人比較入口根據V1.2.2明確研究授權建立，不把V1.2.1的美術／添飯gate改成通過，也不修改正式選片清單。飯匙及卸飯中間態仍不具備自然添飯條件。

## 重建與交付

GitHub只保存非敏感程式、JSON／CSV、報告與雜湊；PNG及MP4在私人審核包，不公開部署素材。審核包收錄開始／中間／結束、切點與移鏡的重點影格，以及全部原始／衍生輸入資產；其餘停留取樣可用腳本重建。

```bash
cd broll-pipeline
python tools/prepare-v122-assets.py --source /private/broll-v122-comparison
node tools/build-v122-timeline.mjs
node tests/comparison-v122.test.mjs
REMOTION_HOST=/private/existing-v2.5-host node tools/render-v122-comparisons.mjs --stills
REMOTION_HOST=/private/existing-v2.5-host node tools/render-v122-comparisons.mjs
python tools/package-v122-comparisons.py
```

依賴沿用原Remotion4.0.539、React、Chromium、TypeScript，以及既有Python Pillow／Playwright／FFmpeg；沒有重建引擎、安裝付費服務、呼叫新圖像生成或GPU。`--variant=A`／`--variant=B`可單獨重建某一方案。內部截圖／bundler使用本機HTTP；iPhone直接開交付MP4或ZIP即可，不需要自行架伺服器或存取雲端localhost。
