# V1.2.1｜原創物件美術審核

本輪只交付三張1080×1920同視角靜態狀態圖及原創PNG物件。沒有4秒動畫、沒有1080影片、沒有串接M1/M2。使用者已保留M1（有視野限制）、M2，並否決舊M3；此結論記錄於新版本，不改寫舊版成果。

原始生成用內建 `image_gen.imagegen`；參考僅限本輪新生成資產。不是Pixabay素材，也不是實拍或量測結果，不套用Pixabay授權。使用方式依所用平台生成服務條款。生成規格及補圖需求見 `GENERATION-PROMPTS.md`。來源PNG、輸出PNG及三張檢查圖都有SHA-256紀錄。沒有虛構模型版本、seed、3D相機標定或生成影像專屬權利保證。

餐盤／蔬菜／蛋白質目前**合在一個固定美術層**：如此可保持三張完全相同；沒有宣稱三者已能個別移動或換菜。若後續要求換菜色／食物獨立遮擋，需要進一步拆層或重新生成。米飯與飯匙已可獨立分層，均為原生alpha物件，不使用舊照片的色鍵遮罩或lighten blending。

## 三張圖如何保持一致

- 完全相同的餐盤底層、位置與尺寸：畫布1080×1920，底層矩形 `[40,450,1000,1000]`。
- A、B、C各用一個獨立完整米飯資產；三者共用原生像素倍率0.52，不把同一飯團平移複製或放大成不同量。
- 對齊同一餐盤的下方空區域，蔬菜、蛋白質不動，沒有用新食物覆蓋它們。接觸陰影是各原創米飯資產的一部分，靜態時與飯團一起放置。
- 標示「概念示意」「相對狀態，不是建議份量」。沒有克數、熱量、固定飲食比例、正確答案勾選，A/B/C也不是醫療、減重或個人化建議。
- `State-*-art-only.png` 關閉文字供美術檢查；不能因此把圖改稱實拍紀錄。

本輪用HTML/瀏覽器進行靜態物件排版與PNG匯出，沒有Remotion動畫渲染，也沒有用SVG／CSS畫食物。匯出圖集只是矩形物件區域的原生像素視窗，不是舊式照片描邊遮罩。原始生成檔保持完整。

## 美術檢查與人審風險

已逐張檢視三張實際輸出：整盤完整可見、白飯可辨、白飯與蔬菜／蛋白質沒有明顯穿透，沒有舊版同一照片反覆疊加的接縫。固定盤／菜／雞肉區域另以像素差異檢查。這些是技術及初步目視結果，**尚非使用者美術核准**。

仍需人工確認：

- 米粒顆粒尺度、濕潤程度和飯堆透視在A/B/C是否足夠一致；生成提示詞相同不等於已標定同一3D相機。
- 原生alpha邊緣在米白／深色背景是否自然；尤其陰影邊緣及圖集分隔處極淡像素。區域匯出未修繪原圖。
- 白飯與固定食物的光影是否協調，飯堆是否有足夠接觸感；小份量的留白與較多狀態是否符合品牌美術，而非飲食建議。
- 飯匙兩種生成形態不能視為同一工具的精確註冊狀態；米飯三態也不是拓撲連續的3D資產。
- 聯絡表只是比較用，請以單張完整圖判斷質感；本輪不因「可播放／可渲染」就視為畫質通過。

## 圖層與動作規劃（尚未實作）

| 層次 | 用途 | 目前是否足夠 |
|---|---|---|
| 固定餐盤／蔬菜／蛋白質底層 | 空間與相同餐點的參照 | 靜態具備；個別食物更換尚需拆層 |
| 落盤白飯狀態 | A、B、C相對狀態 | 靜態具備；動作中間態未具備 |
| 飯匙本體 | 沿有接觸意義的曲線進入／退出 | 有候選，應固定一個本體，不能交換兩把匙 |
| 匙上米飯 | 隨匙運動、接觸後轉移到盤面 | **需要獨立生成／整理**，目前載飯匙把兩者烘焙在一起 |
| 接觸陰影／前後遮擋 | 區分盤面、匙、米飯的深度 | 靜態陰影已烘焙；運動用陰影／遮擋尚未具備 |

建議4秒事件方向仍保留使用者原意：0–0.8秒完整餐盤A；0.8–1.8秒第一個真實可讀的匙面接觸／卸飯事件至B；1.8–2.8秒第二次接觸至C；2.8–4秒平等展示三種相對選項，不突出一個正解。**這不是已排定的動畫時間軸**，也沒有把上述資產判定可直接完成它。

目前素材不能自然支援這兩次卸飯：A/B/C米飯表面會重新排列，工具的前後狀態也不對齊。不能以硬切、淡化或讓飯匙蓋住所有問題區域來掩飾。即使三張靜態獲准，仍須補齊可分離匙上米飯、接觸陰影、註冊中間態並重新檢查。如果無法取得，應先提「三個完整餐盤選項比較」等不冒稱添飯的替代分鏡，再請使用者審核；不強行製作添飯動畫。

## 可重複使用的資料接口

`object-module-draft.json`僅為接口草案，支援：base/layer assets、任意狀態清單、state assets、動作起訖影格、鏡頭尺寸位置、短標題、旁白對齊點。`contract.schema.json`驗證資料形狀，**沒有宣稱通用動畫元件已完成**。只有美術和物件動作測試都通過後，才把這個接口接入原有Remotion；不重建引擎。

`tools/check-v121-art.mjs`核對審核版雜湊與明確美術核准；目前會exit2，原因包括缺少人工核准與動作資產不足。此工具是新的靜態審核入口，不修改舊版gate、Composition或正式素材記錄。

## 重建

GitHub保留非敏感程式、提示詞、配置、雜湊與驗證報告；原始及衍生PNG在私人審核包。取得審核包後，將`assets/`原樣放在`/workspace/outputs/broll-v121-art-review/assets/`。

```bash
cd broll-pipeline
python tools/build-v121-art.py
python tools/capture-v121-art.py
python tools/package-v121-art.py
node tools/check-v121-art.mjs # 尚未核准／動作素材不足應exit2
```

需要既有Python Pillow（只用於圖像資訊、像素檢查、聯絡表）、Playwright及Chromium、Noto Sans CJK。截圖用本機HTTP而非file URI；iPhone不用連雲端localhost，直接開啟交付PNG或ZIP即可。沒有新增付費服務、GPU、配音或影片引擎。
