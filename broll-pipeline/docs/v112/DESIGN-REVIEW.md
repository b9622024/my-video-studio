# V1.1.2：先驗收構圖，再決定是否製作動畫

本輪只有四張1080×1920靜態構圖，以及各自關閉文字的檢查版本。沒有新4秒／12秒MP4，沒有Remotion啟動，沒有新動畫時間軸。V1.1.1的B2／C2A／C2B已依使用者回覆記錄為不採用，但不修改A1／B2／C2既有正式素材核准紀錄。

## 工作優先順序

1. 有真實動作且畫質足夠的B-roll。
2. 真實食物照片／影片配合有實際內容的說明。
3. 有具體參照與可查證來源的比較、機制、數據動畫。
4. 純抽象圖形最後考慮；沒有意義就不做。

素材不足可標記missing或unusable並提出補充來源，不用SVG或幾何運動假裝完成敘事。此次四案不含圓點、弧線、量表、程式繪製的食物或假立體碗盤，也沒有同一張照片拆成大小圖。

## B段兩案

|方案|主角與焦點|文字位置|前後連接|核准後才考慮的事件概念|
|---|---|---|---|---|
|B-01 動作近景|B1原片36秒，鍋鏟托住綠葉菜；工具與食物是主體|下方鍋面暗部，避開中央葉菜|接A1食物近景，再接C的真實主食|蔬菜在鍋內→被鍋鏟托起；使用原影片自然事件，不讓照片層持續漂移|
|B-02 成品銜接|B1原片45秒，實拍綠葉菜成品；紙面與單一照片分層|上方標題、下方短句，不在食物中央疊字|承接原片準備過程，並與C-02的紙面版式一致|原片烹調→原片成品的有目的剪接；沒有拍到的連續裝盤或放便當動作不宣稱存在|

B-01為動作優先，B-02為同一影片中「過程接成品」的另一敘事選項；不是同一張照片換大小模板。B-02照片是成品，不能單獨當成夾菜動作證據。原片背景的花與其他擺飾保留原貌，不判定可食性、不從裝飾推定營養。

初稿原片18秒及14秒的攪拌影格，在9:16放大後動態模糊明顯，已被否決。B-01換成較清楚的托菜瞬間，B-02改為成品段落，沒有用假銳化或生成食物補畫。B1源於實際烹調影片，仍有自然動態模糊；若使用者認為清晰度不足，必須補更清晰的實拍，而非直接進渲染。

## C段兩案

|方案|主角與焦點|文字位置|前後連接|核准後才考慮的事件概念|
|---|---|---|---|---|
|C-01 主食特寫|C1原片4秒，真正熟白飯與米粒|下方紙面資訊區，白飯中央不疊字|接B-01的食物近景與低字量敘事|僅使用原片鏡頭的自然觀察變化；不偽造飯量增減|
|C-02 資訊界線|C1原片12秒，白飯主體配簡潔非量化說明|上方標題及下方短句，單一照片為主|和B-02一致的攝影／文字層級|以有目的的真實主食鏡頭支援「照片不能決定個人需求」；不做進度條或空碗交換|

兩張照片是同一來源在不同時點的觀察，**不是兩份不同份量的證據**。C1沒有盛飯、減飯或可核對的量變過程。如果要講「實際增減多少」，需補拍同餐具、同角度、同光線下的真實操作及前後狀態；若還要標數值，另需真實量測依據。現階段完全不顯示克數、熱量、固定飲食比例或推薦份量。

以上只有前後狀態的敘事可能性，沒有設定鏡頭時長、關鍵影格或動畫時間軸。待靜態構圖獲明確核准後，才設計動態。

## 七項品質否決與人工驗收

1. 關閉全部文字仍能辨認食物主題。
2. 食物與工具為主角；版面照片區約69%–100%，不是食物分割或營養比例測量。
3. 沒有生成／程式繪製的假食物、假立體餐具。
4. 沒有與食物無關的裝飾線、點、框與量表。
5. 文字與照片分層，低字量、不遮擋中央主物件。
6. 是否達到影片構圖而非簡報感，由使用者作最後判斷，不能以自動檢查冒充驗收。
7. 畫面對應配菜與主食概念，不轉移到餐具交換或不明比例。

四案均附無文字版；已做自查與排除模糊初稿，但**目前沒有任何一案取得人工靜態核准**。design-review.json保存影像hash、逐項證據與待判斷事項。任何明確fail、缺素材、版本改變或未取得使用者核准，都會阻擋新流程。

src/design-first.mjs把「靜態構圖核准」與「素材使用核准」分開：未核准構圖，不允許進動畫規劃；有明確品質否決或缺素材，即使有選擇紀錄也不放行；只有構圖核准而未核准B1／C1，仍不允許正式渲染。這是新增的Design-first前置檢查，沒有改寫或停用舊影片引擎。

## 與V1.1.1的差異

|V1.1.1|V1.1.2|

## 重建

```sh
git checkout broll-pipeline-v1.1.2
cd broll-pipeline
mkdir -p .runtime/v112-assets
# 從私人設計包還原來源影格，不需重新下載影片：
cp /path/to/package/assets/B-lift.jpg .runtime/v112-assets/B-lift.jpg
cp /path/to/package/assets/B-prepare.jpg .runtime/v112-assets/B-finished.jpg
cp /path/to/package/assets/C-detail.jpg .runtime/v112-assets/C-detail.jpg
cp /path/to/package/assets/C-plate.jpg .runtime/v112-assets/C-plate.jpg
python tools/build-v112-designs.py
python tools/capture-v112-designs.py
node tests/design-first.test.mjs
node tools/design-first-gate.mjs
```

需要Python Playwright、Chromium與Noto CJK字體。HTML/CSS只用來精確排版和輸出靜態JPEG，沒有animation或transition。內部截圖用loopback HTTP，不需使用者架server；交付JPG可直接觀看。gate命令目前預期exit2，原因STATIC_DESIGN_APPROVAL_REQUIRED，不是故障。將來若JPG變更須更新review及重新驗收，不能沿用舊核准。

Git保存原始碼與非敏感審核JSON；食品影格及設計JPEG保存在私人交付包，不公開建素材庫。所有舊版Composition、API、HyperFrames、GPT-SoVITS、A1／B2／C2核准資料與V1.1預覽均維持原值。

未來若另有明確的素材使用核准，可將私有紀錄以`--materials /private/material-approval.json`交給gate；格式包含project_id、provenance=user_explicit、status=approved、message原始回覆、approved_option_ids。此檔不是由選圖自動建立，也不是改寫舊approved-assets。任一品質檢查標為fail仍會否決。
