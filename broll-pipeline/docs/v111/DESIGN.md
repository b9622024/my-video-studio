# V1.1.1 視覺敘事與小範圍測試

基於V1.1 commit0250187，獨立分支broll-pipeline-v1.1.1。本輪只有B2、C2A、C2B三支4秒／540×960／30fps設計測試，不合成新的12秒片，不輸出1080。原A1＋B2＋C2核准資料、V1.1成片、API、GPT-SoVITS、HyperFrames及原Composition均保留。

## 敘事規則（visual_design）

新專案projects/bento-v111-visual-tests/scene-plan.json以可選visual_design記錄六項：主物件、注意順序、移動物件、可見變化、理解結果、前後連接。schemas/v111/contracts.schema.json新增可選欄位；V1.0及V1.1舊分鏡已驗證相容。這不是改寫已核准分鏡，而是待驗收的設計提案副本。

### B2：同一餐盤，從整體轉到蔬菜

- 主視覺：A1原片4.95秒的同一個餐盤影格。綠葉菜實際可見且解析度足以局部裁切，所以不必換素材。
- 第一注意：首格保留A1的食物全畫面，承接原實拍；沒有突然切深色抽象背景。
- 動作物件：餐盤影像縮入右上脈絡圖，下方同步遮罩揭示實際蔬菜局部。兩張圖都是同源裁切，不生成新食物。
- 可見變化：整盤觀察 → 蔬菜成為大主體＋整盤脈絡仍可對照。
- 理解結果：觀眾能辨認正在觀察餐點中的蔬菜與其他食物。未把肉類擅自標為「配菜」，也未從顏色推定營養。
- 銜接：首格接A1；尾格的照片、米白紙面、深藍字與柔黃標籤接到C2相同語言。

|時間|畫面動作|結果|
|---|---|---|
|0–0.6秒|原餐盤全幅停格|保留原食物與A1脈絡|
|0.6–1.73秒|整盤縮入脈絡小圖，蔬菜實拍局部揭示|注意力從整體轉向真實蔬菜|
|1.73–4秒|保留兩個可對照位置，標註貼近圖像邊緣|看見蔬菜局部與其餐盤來源|

### C2A：純Remotion餐具與盤面參照

- 主視覺：有瓷器深度、接觸陰影及金屬餐具的餐盤和兩個空碗，沒有繪製任何食物。
- 第一注意：辨認餐盤、碗、叉匙，先建立餐桌物件的意義。
- 動作物件：大碗移入餐盤，再回桌面；另一個小碗移到餐盤。
- 可見變化：不同容器占用不同盤面空間，兩個容器仍保留作參照。
- 理解結果：討論的是容器／空間與份量觀察的關係；不是證明應減少多少食物，也不宣稱小碗較健康。
- 銜接：米白、深藍器皿與B2一致，保留真實餐桌物件意義，避免空白背景上的進度條。

此方案只證明餐具與空間，不代表已呈現實際白飯份量。若期待明確看見主食，C2B提供更直接的食物主體；兩案都交由使用者判斷。

### C2B：真實白飯照片＋容器參照（新素材使用提案）

- 主視覺：既有C1已審核的熟白飯來源照片，上方為食物大圖，下方為空餐具參照。
- 第一注意：先看見真正的熟白飯，而非文字或量表。
- 動作物件：白飯照片局部放大，餐盤中的空碗交換位置。
- 可見變化：觀察白飯細節 → 對照不同容器與盤面空間。白飯照片沒有增減、合成或放入繪製的空碗。
- 理解結果：以食物與餐具作非量化參照；不是實拍盛飯／減飯，不是飲食推薦。
- 銜接：沿用B2照片層次與米白／深藍版面，C1原黑盤保留為來源影像的一部分。

|時間|C2A／C2B動作|
|---|---|
|0–0.33秒|辨認餐盤、兩個空容器與餐具；B另有真實白飯大圖|
|0.33–1.6秒|大碗移入盤面；B同時觀察白飯局部|
|2–3.5秒|大碗移回桌面，小碗移入盤面，呈現空間參照變化|
|3.5–4秒|保留比較結果，不顯示克數、熱量、固定比例或推薦量|

C2B採用C1官方API既有回傳的large.thumbnail作私人設計提案，正常GET200，沒有新API搜尋或代理。來源、作者、授權與hash見c1-proposal-source.json。**C1尚未加入正式approved-assets；若選C2B進入成片，需要使用者新增核准C1用途。**

## 美術與元件

PhotoFocus處理同源照片的構圖與遮罩；ContextualAnnotation讓標註跟隨真實物件的圖像邊緣；PortionExplanation處理有空餐盤參照的容器交換。EditorialVisualTest是這次三案的組裝器，並非把所有視覺塞回一個InformationGraphic模板。

原HybridComposition.tsx完全保留，字幕、資料接口與舊動畫可以照舊重建。本輪新元件尚未接管正式12秒時間軸；設計核准後才決定正式整合方式，避免更動既有核准綁定。新增元件均由useCurrentFrame與固定插值計算，不用GSAP、隨機值、時間或播放狀態。

沒有配音或逐字字幕，僅保留與物件有關的編輯標註。另交付三張完全關閉文字的影格，方便評估物件是否成立；這不是對主觀畫面品質的自動驗收。

## 重建與驗證

```sh
cd broll-pipeline
# 使用V2.5同版本既有Remotion runtime，不更改舊引擎。
V11_PROJECT=/path/to/v11/projects/bento-v11 node tools/prepare-v111-assets.mjs
# C1影像若未從私人包還原，明確製作提案時才取正常官方GET：
V11_PROJECT=/path/to/v11/projects/bento-v11 node --use-env-proxy tools/prepare-v111-assets.mjs --with-c1-proposal
REMOTION_HOST=/path/to/v2.5-runtime node tools/render-v111-visual-tests.mjs --stills
REMOTION_HOST=/path/to/v2.5-runtime node tools/render-v111-visual-tests.mjs
```

公開Git不含素材；私人測試包assets/可還原至.runtime/v111-public/assets/，即可省略GET。依賴沿用4.0.539／React19.3.1，需FFmpeg／ffprobe、Chromium及Noto CJK字體。本輪無付費服務、GPU或新搜尋。

驗證：三支120frames／4秒／540×960／30fps H.264全片解碼；TypeScript通過；同一影格90以非順序請求重渲染，三組JPEG逐位元組相同；新Schema與舊分鏡相容；原核准、manifest、時間軸、分鏡與V1.1預覽hash未變。記錄見verification.json。
