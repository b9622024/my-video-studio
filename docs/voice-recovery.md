## 延續順序

1. 先完成下述私人異地備份與復原驗證。
2. 在私人紀錄中核對 A／B 參考逐字稿與歷史生成文字；不要用猜測補齊。
3. 先尋回原環境的模型來源、上游 commit、權重雜湊與依賴清單。若尋不回，列出需取得的精確資產、大小與授權，再由使用者決定是否下載；本輪不下載、不訓練、不使用付費 API／GPU。
4. 若參考 A 長度不符合所選上游版本的限制，從原錄音另存符合限制的乾淨片段，保留原檔與時間範圍，重新核對逐字稿。
5. 固定上游 commit、Python／套件鎖定檔、全部權重雜湊、硬體與推論入口。填寫設定範本中的未知值，保留實際載入權重及參考音檔的日誌。不能僅憑設定檔宣稱成功使用模型。
6. 新建基準時固定文字、參考、seed、語言與所有有效推論參數。此為新基準，不能聲稱重現原 A。每個 run 使用獨立目錄，不覆寫歷史結果。
7. 先比較參考選段／逐字稿準確性，再逐項調整斷句、繁體中文文本正規化、語速及取樣參數。一次只改一項；台灣用語、數字、多音字、英文混讀、長句各有測試句。測試句與完整參數保存在私人紀錄。
8. 以錯字／漏字／重複、台灣語調、聲線相似度、自然度及爆音／截斷評分；記錄使用者盲聽結果。公開報告只用 run ID 與非敏感摘要，避免公開原音或私人逐字稿。

私人資產：目前位於 `/workspace/voice-private`，內有 recovery/、original-recovery.zip、manifest.json；這是暫存副本，不是已驗證的持久儲存。
未配置任何私人雲端／持久磁碟。下一步須指定使用者已有的私人儲存位置；不能聲稱工作已完成持久備份。
原聲、生成音訊、模型權重、私人逐字稿、完整執行日誌都留在非公開儲存。使用存取控制與加密，禁止公開連結；加密金鑰與備份分開保存。
`.gitignore` 是第一層保護，不防止 git add -f。提交前檢查 git diff --cached --stat 並逐檔審查；不要強制加入媒體、權重或備份。

## 備份與新任務復原

1. 在目前工作區執行 `python scripts/private_assets.py verify /workspace/voice-private` 驗證救援檔雜湊。
2. 使用 `python scripts/private_assets.py backup /workspace/voice-private /PRIVATE_PERSISTENT_MOUNT/voice-backup.tar.gz` 建立排他新檔，目的地必須位於已確認的私人持久儲存且在 repo／資產來源目錄外。工具不會建立雲端服務、不會上傳；封存檔本身未加密，僅應放在加密且非公開的儲存中。
3. 保存備份 SHA-256 到私人紀錄，將 Git 分支推送到已確認的遠端。尚未推送就仍只是本機版本；本輪不把私人檔案加入 Git。
4. 新任務先取得 repo 的已記錄 commit，再從私人持久儲存恢復資產至 repo 外。解壓前檢查路徑，復原後再執行 verify；核對模型雜湊及環境鎖定檔。
